title: "Webhooks"
description: "Configure one endpoint to receive signed broker events."

Configure one backend `webhookUrl` for all broker events. The platform sends signed JSON payloads to this URL, and your service routes each payload by `eventType`.

## Implement the Webhook receiver

1. Create a backend HTTPS endpoint that accepts `POST` requests.
2. Preserve the raw request body and verify the signature before processing data.
3. Route the event using `eventType`.
4. Return `2xx` after persisting the event.

<Warning>
Production endpoints must use HTTPS. The Webhook receiver must run on your backend, not in a browser page.
</Warning>

## Common event structure

```json
{
  "eventId": "evt_20357690001",
  "eventType": "broker.transferred",
  "eventVersion": "1.0",
  "occurredAt": 1784454000123,
  "data": {}
}
```

| Field | Description |
| --- | --- |
| `eventId` | Unique event ID and idempotency key |
| `eventType` | Event type used to route the business scenario |
| `eventVersion` | Event schema version |
| `occurredAt` | Event creation time as a Unix timestamp in milliseconds |
| `data` | Business payload for the event type |

## Event types

| Event type | Trigger |
| --- | --- |
| [`broker.transferred`](/en/broker/api-reference/webhooks/broker-transferred) | A broker user transfer succeeds or fails |

## Signature verification

The platform calculates an HMAC-SHA256 signature with the broker App Secret. Each request includes:

- `x-webhook-id`
- `x-webhook-timestamp`
- `x-webhook-signature`

The signature input is:

```text
timestamp + "\n" + webhookId + "\n" + rawBody
```

Verify the signature against the raw request body bytes and use a constant-time comparison. We recommend rejecting requests whose timestamp differs from the current time by more than five minutes.

## Delivery and retries

Delivery uses at-least-once semantics. Persist the event before returning `2xx`. Connection failures, timeouts, and non-`2xx` responses trigger backoff retries, up to 12 attempts.

Create a unique database index on `eventId`. A duplicate event must not apply a balance change again, but the receiver should still return `2xx`.

## Local testing

A local service cannot receive callbacks from the public internet directly. Use ngrok or Cloudflare Tunnel to expose a test endpoint. After confirming that the generated HTTPS URL is reachable, configure it as described in the next section.

## Set the Webhook URL

After implementing and verifying the receiver, call [Update broker settings](/en/broker/api-reference/settings/update) and submit only the `webhookUrl` you want to set:

```http
PATCH https://api-test.topblast.trade/v1/broker/settings
x-app-id: <APP_ID>
x-timestamp: <TIMESTAMP>
x-signature: <SIGNATURE>
Content-Type: application/json
```

```json
{
  "webhookUrl": "https://broker.example.com/webhooks/xbit"
}
```

Omitted `name` and `domain` fields remain unchanged. When calculating the signature, use `PATCH` as the method, `/v1/broker/settings` as the path, and the exact raw JSON sent as the body. See [Authentication](/en/broker/guide/authentication) for the signing rules.

New events are sent to this URL after the update succeeds. Complete an end-to-end test with a test endpoint before switching to the production URL.
