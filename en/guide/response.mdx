---
title: "Common response format"
---

The zpm Broker OpenAPI uses a consistent response format so clients can handle errors and parse data uniformly.

## JSON response

Every request returns a JSON object containing `code`, `message`, and `data`.

| Field | Type | Description |
| :--- | :--- | :--- |
| `code` | `int` | Status code. **200** means success; any other value means failure. |
| `message` | `string` | Result description. Successful requests usually return `"success"`; failed requests return the error reason. |
| `data` | `object` | Business data. This value may be `null` when the request fails. |

## Examples

### Successful response

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "uid": 1000000000001
  }
}
```

### Failed response

```json
{
  "code": 401,
  "message": "Invalid signature",
  "data": null
}
```

## Status codes

- **200**: Request completed successfully
- **400**: Parameter validation failed
- **401**: Authentication failed because the API key, signature, or timestamp is invalid
- **404**: The requested resource, user, or broker does not exist
- **429**: Rate limit exceeded
- **500**: Internal server error
