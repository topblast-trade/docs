Welcome to ZPM OpenAPI. This documentation is for brokers and partners integrating with the ZPM trading platform from their servers. It explains Broker API authentication, the integration flow, and available capabilities.

## Capabilities

After integration, your broker server can use the Broker API to manage:

1. **Users**: Map broker users to ZPM users, synchronize login tokens and logout state, update user details, create special accounts, and list users under the broker.
2. **Assets**: Create deposits or withdrawals, query transfer records and details, and retrieve user assets and balances.
3. **Trading**: Query trades, positions, and open orders, and perform actions such as canceling orders and closing positions.
4. **Reports**: Retrieve summary, trend, daily summary, and dashboard data for user growth, activity, fund flows, and trading volume.
5. **Events**: Query platform events and markets, and enable or disable events for the broker.
6. **Risk management**: Query policies and exposures, and read or save global and event-level risk settings.

All endpoints use the `/broker/v2/*` prefix and must be called from the broker server. Requests are authenticated with an API key, timestamp, and HMAC-SHA256 signature and can access only data within the current broker's scope.

<Warning>
Store the API Secret on the broker server only. Never expose it to browsers, mobile clients, or end users.
</Warning>

## Prerequisites

Obtain a broker-level `API Key` and `API Secret` from ZPM and confirm access to the test environment. Every request must include `x-api-key`, `x-timestamp`, and `x-signature`. See [Broker API authentication](/en/guide/authentication-b).

## Standard integration flow

After a broker user signs in, call `POST /broker/v2/user/login` from the broker server to synchronize the broker user ID and token with ZPM. ZPM automatically creates the mapping if it does not exist.

```mermaid
sequenceDiagram
    autonumber
    participant Broker as Broker server
    participant ZPM as ZPM trading platform
    Broker->>Broker: User signs in and receives a token
    Broker->>ZPM: POST /broker/v2/user/login<br/>Signed request with userId and token
    ZPM-->>Broker: Return the platform user UID
    Broker->>ZPM: Call another /broker/v2/* endpoint<br/>with signed headers
    ZPM-->>Broker: Return the result
```
