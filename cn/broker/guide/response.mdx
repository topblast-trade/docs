---
title: "通用响应结构"
description: "了解 Broker REST API 的成功响应、统一错误响应、分页方式和 HTTP 状态码。"
---

Broker REST API 使用 HTTP 状态码表示请求处理结果。成功响应直接返回接口定义的数据，不再统一包裹 `code`、`message` 或 `data`；失败响应统一返回 `error` 字段。

## 成功响应

成功请求返回 `2xx` HTTP 状态码，响应体以对应接口的 Schema 为准。

### 页码分页

支持页码分页的列表接口接收 `page` 和 `size`，返回当前页数据及总数：

```json
{
  "items": [
    { "userId": "10001", "email": "user@example.com" }
  ],
  "total": 10
}
```

`page` 从 `1` 开始，`size` 为每页数量，最大值以接口定义为准。

### 流式分页

支持流式分页的列表接口接收 `begin`、`end` 和 `size`，返回时间范围内的数据：

```json
[
  { "txnId": "txn-10001", "state": "SUCCESS", "createdAt": 1784621855801},
  { "txnId": "txn-10002", "state": "PROCESSING", "createdAt": 1784621855801}
]
```

`begin` 为开始时间（Unix 毫秒，包含），`end` 为结束时间（Unix 毫秒，不包含），`size` 为返回数量。请以具体接口页面声明的参数和响应 Schema 为准。

<Note>
创建划转成功时通常返回 HTTP `201`；如果请求已受理但仍在异步处理中，则返回 HTTP `202`。登出和更新用户等无响应体操作返回 HTTP `204`。
</Note>

## 失败响应

失败请求返回对应的 `4xx` 或 `5xx` HTTP 状态码，并使用统一 JSON 结构：

```json
{
  "error": "invalid request"
}
```

## 常用 HTTP 状态码

| HTTP 状态码 | 含义 | 建议处理方式 |
| :--- | :--- | :--- |
| `200 OK` | 查询或更新请求成功 | 按当前接口的响应 Schema 解析响应体。 |
| `201 Created` | 资源创建成功 | 保存响应中的新资源或资源标识。 |
| `202 Accepted` | 异步请求已受理 | 保存划转标识，通过详情接口或 Webhook 跟踪最终状态。 |
| `204 No Content` | 操作成功且无响应体 | 不要尝试解析 JSON。 |
| `400 Bad Request` | 参数、请求体或签名原文格式无效 | 修正请求后再提交，不要原样重试。 |
| `401 Unauthorized` | API Key、时间戳或签名无效 | 检查鉴权 Header、时间戳和签名计算。 |
| `403 Forbidden` | 当前券商无权执行该操作 | 检查券商权限和资源归属，停止无效重试。 |
| `404 Not Found` | 路由或资源不存在 | 检查资源 ID、用户 ID 和请求路径。 |
| `409 Conflict` | 资源状态冲突（例如重复划转） | 查询资源当前状态，再决定是否重试。 |
| `500 Internal Server Error` | 服务内部错误 | 记录请求上下文并采用退避策略重试。 |

具体接口支持的状态码和响应 Schema 以各 API Reference 页面为准。
