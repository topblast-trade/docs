topblast Trading REST API 使用 HTTP 状态码表示请求处理结果。成功响应直接返回各接口定义的业务数据；失败响应采用统一的 JSON 结构，便于客户端集中处理错误。

## 响应规范 (JSON)

### 成功响应

成功请求返回 `2xx` HTTP 状态码。响应体结构由具体接口定义，不额外包裹 `code`、`message` 或 `data` 通用外层。

例如，查询当前委托成功时返回：

```json
{
  "data": [
    {
      "id": "8001",
      "status": "OPEN",
      "market": "7001",
      "assetId": "101",
      "side": "BUY",
      "originalSize": "10",
      "sizeMatched": "0",
      "price": "0.41",
      "outcome": "YES",
      "orderType": "GTC",
      "expiration": "0",
      "createdAt": 1710000000000,
      "reasonCode": 0
    }
  ],
  "count": 1
}
```

<Note>
请以每个接口页面中的响应 Schema 为准。批量异步下单受理成功时返回 HTTP `202`，其他成功请求通常返回 HTTP `200`。
</Note>

### 失败响应

失败请求统一返回包含 `code` 和 `error` 字段的 JSON 对象。

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `code` | `int` | 稳定的业务错误代码。客户端可以使用该字段进行分支处理。 |
| `error` | `string` | 可读错误信息，通常包含稳定错误标识和具体失败原因。 |

例如，私有接口缺少有效 Token 时返回：

```json
{
  "code": 1103,
  "error": "REJECT_ANONYMOUS"
}
```

<Warning>
请同时检查 HTTP 状态码和响应体中的 `code`。不要依赖 `error` 文本进行稳定的业务判断，因为错误详情可能随服务端版本调整。
</Warning>

<Note>
有关 HTTP 状态代码和业务错误代码，请参阅[错误代码](/cn/user/guide/errors)。
</Note>
